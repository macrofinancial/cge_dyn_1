What this model does

This is a 4-sector, 2-factor recursive-dynamic computable general equilibrium model (31 annual periods), calibrated from a 2005 social accounting matrix and built in GAMSPy. Production nests Cobb–Douglas value-added over CES factor demand; trade uses an Armington CES import/domestic aggregate and a CET export/domestic transformation; capital accumulates period to period (KKt+1 = (1−δ)KKt + IIt) and labor grows with population. The experiment abolishes the import tariff (taum → 0) in every period and compares the resulting path to business-as-usual.

How this page gets its numbers

Solving this model needs a real GAMS engine/license, which wasn't available where this page was first built, so the initial dataset was digitized from the source notebook's own saved output (the charts and printed summary from a run with real GAMS) by pixel-calibrating each matplotlib figure against its axes. Values at period 0 and 30 match the notebook's printed text exactly; periods 1–29 were read off the plotted curves. See data/ and export_for_dashboard.py in this repo for the exact export path and how to replace this with a full-precision GAMS-solved export.

Findings on the notebook

  • bugThe first, "official" run silently produces a near-zero result. The notebook's own saved output shows two back-to-back executions: calling results.main() prints EV_TTL: -0.0 and every deviation at 0.000%, while immediately rebuilding the model by hand in the same kernel gives the real result, EV_TTL: 5,741.29. The tariff shock is identical in both calls, so this points to state leaking across two Container()/model builds in one GAMSPy process — the notebook's primary entry point (main()) is not safe to trust on its own.
  • bugcompute_results() drops dF from its return value. The function builds a factor-allocation deviation parameter internally but returns a dict without it. The later cell that reads it (dF = out.get("dF", None) then dF.records) will raise AttributeError the first time it's run after a fresh compute_results() call.
  • watchTwo "kept as in original" quirks are flagged in comments but not resolved: eqpf2[h_mob, i, j] equates pf[h_mob, j] to pf[h_mob, i] for every (i, j) pair rather than pinning to one reference sector, and eqPRICE weights pq[j] by the alias j where the rest of the block uses i.
  • watchThe baseline solve is pinned to an exact assertion (math.isclose(dyncge.objective_value, 539570.5027, rel_tol=0.001)). Useful as a regression guard, but it will hard-fail the whole pipeline if the SAM, elasticities or growth assumptions ever change.

Reading the scenario slider

Every series above except trade volumes is already a deviation from business-as-usual, so it's exactly zero under no policy change. The slider scales that deviation linearly between 0% (BAU) and 100% (the GAMS-solved full abolition) to let you explore intermediate tariff cuts; it's a simplification for interactivity, not a separate equilibrium solve.
